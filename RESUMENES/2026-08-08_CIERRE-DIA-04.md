## 2. Sistema de comunicaciones

Objetivo:

> Transferir información entre una fuente y un destino de forma confiable y lo más fiel posible.

Componentes:

```text
Fuente
   ↓
Transmisor
   ↓
Medio
   ↓
Receptor
   ↓
Destino
```

### Fuente

Genera la información.

### Transmisor

Adapta/emite la señal para poder viajar por el medio.

### Medio

Camino físico o inalámbrico por el que se transmite.

Ejemplos:

- fibra;
- coaxial;
- radiofrecuencia.

### Receptor

Recibe la señal y permite recuperar la información.

### Destino

Entidad final que utiliza la información.

---

## 3. Protocolo

Un protocolo es un conjunto de reglas que permite la comunicación entre entidades.

Sus componentes principales:

```text
Sintaxis
→ estructura y formato

Semántica
→ significado y acciones

Temporización
→ velocidad, secuenciación y tiempos
```

Analogía:

> El protocolo es el idioma y las reglas compartidas que permiten a los participantes entenderse.

## 4. Modelo OSI

Orden ascendente:

```text
7 Aplicación
6 Presentación
5 Sesión
4 Transporte
3 Red
2 Enlace
1 Física
```

Para escribirlo desde capa 1:

```text
1 Física
2 Enlace
3 Red
4 Transporte
5 Sesión
6 Presentación
7 Aplicación
```

### Resumen funcional

| Capa | Función principal |
|---|---|
| 7 Aplicación | Servicios a las aplicaciones |
| 6 Presentación | Representación/formato de datos |
| 5 Sesión | Gestión del diálogo |
| 4 Transporte | Comunicación extremo a extremo, segmentación y puertos |
| 3 Red | Direccionamiento lógico y encaminamiento |
| 2 Enlace | Tramas, MAC y acceso al medio |
| 1 Física | Bits, señales y medio |

## 5. TCP/IP

No es un único protocolo.

> TCP/IP es una arquitectura o pila de protocolos utilizada en las redes actuales.

Capas estudiadas:

```text
Aplicación
Transporte
Internet
Acceso a la red
Física
```

Correspondencia:

```text
OSI Aplicación     ┐
OSI Presentación   ├→ TCP/IP Aplicación
OSI Sesión         ┘

OSI Transporte → TCP/IP Transporte
OSI Red        → TCP/IP Internet
OSI Enlace     → TCP/IP Acceso a la red
OSI Física     → TCP/IP Física
```

## 6. Encapsulamiento

Cada capa agrega información de control necesaria para prestar su servicio.

Cadena simplificada:

```text
Aplicación  → datos
Transporte  → segmentos
Red         → paquetes
Enlace      → tramas
Física      → bits
```

En el receptor se realiza el proceso inverso:

```text
bits
↓
tramas
↓
paquetes
↓
segmentos
↓
datos
```

Esto es el **desencapsulamiento**.

---

## 7. PDU

PDU significa Protocol Data Unit.

No es solamente “el dato”.

```text
PDU = datos + información de control
```

Una formulación más formal:

```text
PDU = SDU + PCI
```

- SDU: información proveniente de la capa superior.
- PCI: información de control agregada por el protocolo.

---

## 8. Direccionamiento

### MAC

```text
MAC → capa 2 → enlace → trama
```

Dirección física utilizada para entregar información en el enlace local.

### IP

```text
IP → capa 3 → red → paquete
```

Dirección lógica que permite identificar interfaces/redes y realizar encaminamiento.

No debe definirse únicamente como dirección “fuera de la LAN”.

### Puerto

```text
Puerto → capa 4 → proceso o servicio
```

Permite identificar qué aplicación/proceso debe recibir la información dentro del host.

---

## 9. Switch y router

### Switch

```text
Capa: 2
Dirección: MAC
PDU: trama
Ámbito típico: LAN
Función: conmutación de tramas entre interfaces
```

### Router

```text
Capa: 3
Dirección: IP
PDU: paquete
Función: interconectar redes y decidir encaminamiento
```

Fórmula:

```text
Switch → MAC → trama → LAN
Router → IP  → paquete → redes
```

## 10. Errores que deben recuperarse

```text
TCP/IP ≠ un único protocolo
TCP/IP = arquitectura/pila

PDU ≠ solo datos
PDU = datos + control

IP ≠ solo fuera de LAN
IP = direccionamiento lógico

Puerto ≠ puerta del equipo
Puerto = proceso/servicio
```
